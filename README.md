# کیبورد کرم (CreamIme)

پروژهٔ آغازین یک **Android IME واقعی** با Kotlin است؛ تصویر ارسالی فقط مرجع ظاهر بوده است. پوستهٔ سفیدِ شیری، کلیدهای فارسی/انگلیسی، ردیف ابزار، پیشنهادهای نمونه، و انتخاب‌گر سند در این نمونه پیاده شده‌اند. این پروژه فایلِ تصویری تولید نمی‌کند.

## نکتهٔ مهم دربارهٔ اندازه و طرح

- چیدمان هر ردیف ۱۲ خانهٔ هم‌اندازه دارد؛ کلیدهای واقعی در هر خانهٔ یکسان و با ارتفاع ثابت ۴۲dp هستند. فاصلهٔ افقی و عمودی حدود ۱dp است. جاهای خالی فقط برای حفظ شبکهٔ یکسان‌اند.
- بنابراین Space عمداً یک خانه است، نه کلید عریض استاندارد. روی گوشی باریک، کلیدها از صفحه‌کلیدهای معمول باریک‌تر می‌شوند؛ این پیامد مستقیم شرط «همه دقیقاً هم‌اندازه» است.
- «؟»، «.» و «،» پشت سر Space قرار دارند. رنگ بدنه و کلیدها کرم/سفیدِ شیری است.
- ردیف ابزار: Past، UnDo، ReDo، Select، Tool، Copy و چهار فلش. «Past» همان برچسب درخواستی است؛ فرمان آن Paste اندروید است.
- Caps در چیدمان انگلیسی: یک‌بار = بزرگ‌کردن حرف بعدی؛ دوبار = روشن/خاموش‌کردن Caps Lock؛ نگه‌داشتن = پاک‌کردن حالت Caps. در حروف فارسی بزرگی/کوچکی وجود ندارد.
- Send از `EditorInfo` و `InputConnection.performEditorAction` استفاده می‌کند و در صورت نبود کنش مناسب، Enter می‌فرستد.

## روش سریع: GitHub بسازد و APK بدهد

1. فایل ZIP را باز و پوشهٔ `cream-ime` را استخراج کن.
2. در GitHub یک مخزن خالی بساز؛ مثلاً `cream-ime` (README خودکار نساز تا تعارض پیش نیاید).
3. فایل‌های داخل پوشه را در ریشهٔ مخزن قرار بده؛ پوشهٔ `.github` را هم نگه‌دار. در وب‌سایت GitHub از **Add file → Upload files** استفاده کن، یا با Git push کن.
4. تغییرات را روی شاخهٔ `main` ثبت کن. در مخزن، زبانهٔ **Actions** را باز کن و اجرای **Android debug APK** را صبر کن.
5. اجرای سبز را باز کن؛ در بخش **Artifacts** فایل `cream-ime-debug-apk` را دانلود و از ZIP بیرون بیاور. این `app-debug.apk` برای نصب آزمایشی است، نه انتشار امضاشده.
6. نصب APK خارج از فروشگاه ممکن است نیازمند اجازهٔ «Install unknown apps» برای برنامهٔ دانلودکننده باشد. فقط APK ساخته‌شده از مخزن خودت را نصب کن.

Workflow از JDK 17، Gradle 8.9 و Android SDK 35 استفاده می‌کند. با هر push به `main` یا `master` و هر Pull Request اجرا می‌شود. هیچ راز یا کلید امضایی در مخزن لازم نیست.

## ساخت محلی با Android Studio

1. Android Studio و JDK 17 نصب کن؛ در SDK Manager، Android SDK Platform 35 و Build Tools 35.0.0 را نصب کن.
2. چون این بسته فایل باینری `gradle-wrapper.jar` را حمل نمی‌کند، Gradle 8.9 را روی سیستم نصب کن و در ترمینال ریشهٔ پروژه اجرا کن:

   ```bash
   gradle --version
   gradle assembleDebug
   ```

3. خروجی آزمایشی: `app/build/outputs/apk/debug/app-debug.apk`.
4. برای Android Studio، پوشهٔ پروژه را باز کن و Gradle محلی 8.9 را به‌عنوان Gradle distribution انتخاب کن؛ اگر Sync خودکار انجام نشد، در ترمینال دستورهای بالا را اجرا کن.

## فعال‌کردن و تست

1. APK را نصب و برنامهٔ «کیبورد کرم» را باز کن.
2. دکمهٔ **فعال‌کردن کیبورد** تنظیمات سیستم را باز می‌کند؛ کیبورد کرم را فعال کن.
3. **انتخاب کیبورد** را بزن و کیبورد کرم را انتخاب کن.
4. در کادر آزمایش تایپ کن: حروف، Space، علائم، فلش‌ها، Caps، Paste/Copy، Undo/Redo و Enter را جداگانه امتحان کن.
5. در یک مرورگر آزمایشی، فرم متنی معمولی و سپس فیلد جست‌وجو را امتحان کن. رفتار Send/Enter به نوع فیلد و خود مرورگر بستگی دارد.
6. فیلد گذرواژه را امتحان کن؛ پیشنهادهای واژه و Undo/Redo از کار می‌افتند. کد عمداً متن را به هیچ سروری نمی‌فرستد.

## محدودیت‌های مهم Android IME و دکمه‌های Send/File

### Send و سایت‌ها

IME فقط از راه `InputConnection` با فیلد متنیِ برنامهٔ جلویی حرف می‌زند. به DOM صفحه، دکمهٔ ارسال سایت، نشست کاربری یا شبکهٔ سایت دسترسی ندارد. `Send` تلاش می‌کند action اعلام‌شدهٔ فیلد (مثل SEND/GO/SEARCH/DONE) را اجرا کند و اگر نباشد Enter می‌فرستد؛ اینکه فرم واقعاً ارسال شود را برنامه/مرورگر و سایت تعیین می‌کنند. اجرای قطعی دکمهٔ یک سایت از کیبورد عمومی ممکن نیست و نباید با Accessibility یا تزریق کلیک پنهانی دور زده شود.

### File و بارگذاری در همان سایت

`File` انتخاب‌گر رسمی Android Storage Access Framework را باز می‌کند. پس از انتخاب، نمونه فقط زمانی محتوا را با `commitContent` به فیلد می‌دهد که برنامهٔ مقصد نوع MIME را در `EditorInfo` اعلام کرده و rich-content را بپذیرد. بسیاری از فیلدهای وب و ورودی‌های معمولی این قابلیت را ندارند؛ در آن حالت پیام می‌دهد از دکمهٔ پیوست خود سایت استفاده شود. کیبورد عمومی نمی‌تواند عنصر `<input type=file>` یا روند آپلود سایت را کنترل کند. پشتیبانی `commitContent` در این پیاده‌سازی به Android 7 / API 25 یا بالاتر وابسته است.

برای اتصال اختصاصی به سایت خودت باید خود سایت/اپ مقصد نیز تغییر کند: وب‌سایت باید دکمهٔ upload و مجوز/انتقال فایل خودش را داشته باشد؛ اپ اندرویدیِ تحت مالکیت خودت می‌تواند قرارداد MIME و دریافت محتوای IME را پشتیبانی کند. URI فایل را به متن خام تبدیل یا برای سرور ناشناس ارسال نکن.

### امنیت و حریم خصوصی

- مانیفست مجوز INTERNET ندارد؛ متن تایپ‌شده به بیرون ارسال نمی‌شود.
- IME از نظر Android جزء سطحِ حساس سیستم است: کاربر باید آگاهانه آن را فعال کند. هر کلیدی که کاربر می‌زند بالقوه قابل مشاهدهٔ IME است.
- قبل از انتشار، کد، مجوزها، SDKهای وابسته و APK را بازبینی کن؛ به‌خصوص هرگز ثبتِ کلیدها، متن‌های فرم، رمزها یا ارسال telemetry اضافه نکن.
- Android و برنامهٔ مقصد می‌توانند دسترسی IME را در فیلدهای امن محدود کنند. این نمونه در فیلدهای گذرواژه پیشنهادها و تاریخچهٔ ویرایش را غیرفعال می‌کند.
- Undo/Redo محلی و محدود به تغییرهایی است که همین کیبورد در همان نشست انجام داده؛ حرکت مکان‌نما، تغییر خارجی یا ویرایش هم‌زمان اپ ممکن است تاریخچه را نامعتبر کند. این جایگزین Undo عمومی سیستم نیست.
- پیشنهادهای فعلی فقط چند واژهٔ نمونه‌اند؛ مدل پیش‌بینی واقعی، فرهنگ لغت و شخصی‌سازی هنوز اضافه نشده‌اند.

## Pydroid 3

Pydroid 3 برای اجرای Python است، نه Android SDK/Gradle؛ به‌تنهایی APK این پروژهٔ Kotlin را نمی‌سازد. می‌توان از آن برای ویرایش فایل متنی استفاده کرد، اما برای توسعهٔ Android از Android Studio و برای ویرایش سریع موبایلی از GitHub Web یا یک ویرایشگر + Termux/Git استفاده کن. APK را ساده‌تر است GitHub Actions بسازد. کلید امضای انتشار را در Pydroid یا مخزن عمومی نگه ندار.

## انتشار واقعی

`assembleDebug` فقط APK آزمایشیِ debug می‌سازد. برای انتشار، در Android Studio از **Build → Generate Signed Bundle / APK** استفاده کن و keystore را بیرون از Git نگه‌دار. نسخهٔ `versionCode` را افزایش بده، روی چند دستگاه/نسخهٔ Android و چند برنامهٔ میزبان آزمایش کن، سیاست حریم خصوصی و توضیح مجوزها را آماده کن و سپس طبق الزامات فروشگاه مقصد انتشار بده. APK release فعلی عمداً بدون امضاست.
